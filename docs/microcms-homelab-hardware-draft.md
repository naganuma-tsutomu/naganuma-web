## 3台のProxmoxノードに自宅の環境を集約

自宅で利用するストレージ、監視、開発環境、ホームオートメーションなどを、3台のProxmox VEノードに集約しています。

すべてを高性能な1台へ詰め込むのではなく、処理能力を担当するメインノードと、消費電力を抑えて常時稼働させる補助ノードを組み合わせました。用途に応じてLXCコンテナとKVM仮想マシンを使い分け、サービスごとに必要な分離レベルを確保しています。

この記事では、ホームラボを構成するハードウェアと、その上で動かしている仮想化環境を紹介します。

> 構成スナップショット：2026年9月22日  
> 台数や稼働状況は確認時点の値です。

## クラスタ全体の構成

クラスタ名は`MyHomeCluster`で、Proxmox VE 9.2.11を利用しています。3ノードがそれぞれ1票を持つCorosyncクオーラム構成で、確認時点では3/3票がそろった状態です。

| 項目 | 構成 |
| --- | --- |
| Proxmoxノード | 3台 |
| CPU | 合計14コア／20スレッド |
| Proxmox上の認識メモリ | 合計108GiB |
| 稼働中のゲスト | 32台（LXC 24台、VM 8台） |
| 登録ゲスト | 38台（LXC 27台、VM 11台） |

登録ゲスト数には、稼働中のゲストだけでなく停止中の環境も含まれます。常時利用するサービスに加え、検証時だけ起動する環境を同じクラスタ内で管理しています。

## LXCとKVM VMの使い分け

Proxmox上のすべてのサービスを、同じ形式では動かしていません。軽量さを優先するものはLXC、OS単位の独立性が必要なものはKVM VMへ配置しています。

### LXCを選ぶもの

単機能のLinuxサービスは、主にLXCコンテナで運用しています。VMより少ないリソースで起動でき、バックアップや再起動も短時間で済むためです。

監視、ダッシュボード、ファイル同期、自動化ツールなど、小さく分割できるサービスをLXCへ配置しています。

### KVM VMを選ぶもの

Dockerホスト、Kubernetes、Windows 11、Home Assistantなどは、KVM仮想マシンとして分離しています。

独立したカーネルやOSが必要な環境、コンテナをさらに実行するホスト、アップデートの影響範囲を明確にしたいワークロードはVMを選んでいます。LXCより使用リソースは増えますが、環境ごとの独立性を優先しています。

## クラスタ上で動かしている環境

現在は、用途の異なるサービスを次のようなグループに分けて運用しています。

| 分類 | 主な環境・サービス |
| --- | --- |
| ストレージ・メディア | Nextcloud、Samba、Jellyfin、Syncthing |
| 監視・自動化 | Prometheus、Grafana、n8n、Terraform検証環境 |
| コンテナ・開発 | Docker VM 2台、Ubuntu Server、Windows 11 VM |
| Kubernetes | control plane 1台、worker 2台 |
| スマートホーム | Home Assistant、MagicMirror |
| 個人向けサービス | Vaultwarden、NocoDB、PostgreSQL |

Kubernetesは、control plane 1台とworker 2台で構成した検証・運用環境です。control planeは単一構成のため、Kubernetes自体の高可用性を目的としたクラスタではありません。

サービスの数を増やすこと自体ではなく、障害や更新の影響範囲を分け、必要に応じて作り直せる環境にすることを重視しています。

## ストレージの使い分け

ゲストの仮想ディスクと大容量データは、用途に応じて配置先を分けています。

- **local-lvm**：Proxmox標準のLVM-thin領域。一般的なゲストのシステムディスクに使用
- **local-ZFS**：メインノードのZFSプール。NextcloudやJellyfinなど、容量が増えやすいデータに使用
- **zfs-share**：クラスタ内で利用しているZFSベースのストレージ領域
- **Proxmox Backup Server**：VMとLXCのバックアップ先として使用

ゲストのシステム領域と、メディアやクラウドストレージのように増加量が大きいデータを分けることで、容量管理をしやすくしています。

バックアップの保持方法や外部ストレージとの連携については、ストレージとバックアップを扱う別の記事で詳しく紹介する予定です。

## 異なる世代のハードウェアを組み合わせる

このクラスタは、AMDとIntel、デスクトップ向けCPUと省電力CPUが混在する構成です。同じ性能のノードを3台そろえるのではなく、それぞれの特徴に合った役割を持たせています。

一方で、異なるCPUベンダー間では、VMのCPU設定や実行中の移行に制約が生じる場合があります。そのため、すべてのVMを無停止で自由に移動できる構成とはせず、必要に応じて停止を伴う移行も選択肢に含めています。

同一構成による完全な冗長化よりも、手元にあるハードウェアを活用しながら、負荷分散と保守性を高めることを優先したホームラボです。

## 運用で重視していること

- **小さく分離する**：単機能サービスはLXC、独立性が必要な環境はVMにする
- **役割を分散する**：負荷と重要度に応じて3ノードへ配置する
- **状態を確認できるようにする**：PrometheusとGrafanaでリソース使用状況を可視化する
- **復旧できる形を保つ**：Proxmox Backup ServerへVMとLXCをバックアップする
- **段階的に変更する**：既存サービスを止めず、小さな単位で構成を更新する

## まとめ

3台のProxmoxノードを組み合わせることで、高性能なメインノードだけに依存せず、用途に応じてワークロードを分散できる環境を構築しました。

LXCの軽量さとKVM VMの独立性を使い分けることで、ストレージ、監視、開発、スマートホームといった性質の異なる環境を、同じクラスタ上で管理しています。

今後も、ハードウェアを一度に入れ替えるのではなく、必要な部分からストレージやノードを更新しながら運用を続ける予定です。

VLAN、外部公開、リモートアクセスなどのネットワーク設計については、この記事から分離し、別の記事で紹介します。
